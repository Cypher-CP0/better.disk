Better Disk Manager Windows Design Document

Version 0.1 · 9 October 2026 · Proposed implementation baseline

Better Disk Manager is a Windows desktop application that helps people understand what occupies their storage, investigate changes, and review files before removing them. This document defines the interface and user experience for the first release. The accompanying specification defines the implementation requirements and acceptance criteria.

The first release uses a green treemap based on the supplied sketch. Rectangle area represents storage size. Shade represents a selected time metric, with an explicit unknown state. It does not claim to measure access frequency or decide whether a file is safe to delete.

1 Product direction

The primary user is a Windows user whose drive is filling up and who wants to identify large files without manually inspecting many folders. Developers with large project dependencies are a secondary audience for later specialized views.

The main questions are:

  • What is occupying space on this drive?
  • Which large items have old modification or access dates?
  • What grew since my previous scan?
  • What exactly will happen if I remove this selection?

The interface should lead from an overview to evidence about a specific item. The product's proposed advantage is a readable map, clear size accounting, and scan comparisons. These are product hypotheses to validate with users, rather than claims of market uniqueness.

2 Release boundaries

The first release includes drive and folder scans, a treemap and synchronized list, category filters, item details, local scan history, comparisons, pinned exclusions, and reviewed recycling of eligible personal files. Apps appear through recognized installation roots where they can be identified; the interface clearly labels incomplete attribution.

Downloads is a category of existing files. A download transfer engine, browser extension, duplicate-content scanner, automatic cache cleaner, full app uninstaller, continuous activity monitor, and macOS release are later work. Recycle Bin management opens Windows' own interface; the first release does not empty it.

Better Disk Manager is a working product name. Branding and price remain undecided. The initial experience requires no account and works offline.

3 Reference and proposed layout

The supplied sketch establishes the category sidebar, drive switcher, and green rectangles. The proposed layout retains those elements and adds scope totals, a legend, synchronized navigation, and a details panel.

The wireframe uses illustrative data. Its example is a completed folder scan with a minimum size filter, not a full accounting of a drive. It is a layout reference rather than a final brand design.

Window structure

  1. A native title bar preserves Windows minimize, maximize, close, dragging, and snap behavior.
  2. The toolbar contains the drive or folder selector, Scan or Rescan, and search. Scan status remains visible.
  3. The left sidebar contains All files, Apps, Downloads, Documents, Videos, Archives, Music, Images, Other, and System. History and Settings are secondary navigation. Recycle Bin is an explicitly marked Windows shortcut.
  4. The summary shows drive capacity and available space separately from measured scan totals. It identifies the selected root, scan time, and any incomplete coverage.
  5. The main workspace contains breadcrumbs, size and date filters, the color metric, the legend, and the treemap. A list below the map uses the same dataset and selection.
  6. The right details panel shows the selected item's evidence and allowed actions. Review selection opens a cleanup dialog rather than executing a filesystem change.

At 1280 × 800 logical pixels, use a 180 px sidebar, approximately 300 px details panel, and flexible center. At 1024 × 700, the details panel becomes a drawer and the map/list toggle replaces the split view. Windows scaling changes physical pixels without reducing readable text. The minimum usable layout must be verified at 200 percent scaling.

4 Treemap behavior

Area and hierarchy

Default area uses measured allocated bytes, labeled Size on disk. Users may switch to File size to use logical bytes. Those metrics remain consistent across the map, list, percentages, and selection summary. Unknown allocated sizes are excluded from the quantitative map and listed separately with a visible count.

At a folder level, each block represents an immediate child file or folder. Folder area is the sum of matching descendant files. Click selects; double-click or Enter opens a folder inside the application. File activation opens details rather than launching the file. Breadcrumbs and Alt plus Left navigate back.

Use a squarified treemap with stable size ordering and a path tie-breaker. Preserve selection when filters change. If the item no longer matches, show that state in details and remove its map highlight. Keep the map stable during a scan; publish a provisional map on request and finalize its layout when scanning ends.

Use subtle 2 px gutters and small corner radii. Large gaps and heavily rounded corners distort visual area. Aggregate rectangles too small to select into a Smaller items block that opens the corresponding list. Zero-byte items remain searchable in the list.

Shade and measurement

Default the metric to Last modified. Last accessed is selectable and carries an explanation: “Access dates may be unavailable or outdated. Background software can also access files.” A future or invalid date maps to Unknown. Bucket calculations use elapsed time from the recorded scan start, so a saved scan does not silently change color over time.

For folders and app groups, show the distribution of measured bytes across date buckets in details. The block shade uses the bucket containing the most bytes; ties between known buckets choose the more recent bucket. If unknown bytes are the largest group or tie for largest, use Unknown. The tooltip explicitly says Dominant date bucket, rather than implying that every file has the same age.

Colors are accompanied by labels, dates, list columns, and a legend. Green indicates time age only. Selection uses an independent outline. Warnings use an icon and text so they cannot be confused with age shading.

Filters and denominator

Combine category, name/path search, minimum size, and date filters with AND. A minimum size filter applies to individual files, then folders aggregate surviving descendants. Label it Files at least, so a folder containing many small files is not unexpectedly treated as a large matching file.

Display “Showing 88 GB across 5 matching files” for the wireframe example. Each block's percentage is of the known bytes in the displayed result, not of total drive capacity. A separate drive summary retains the drive denominator. Filtering must never change the reported drive capacity.

5 Primary user journeys

Find a large personal file

The user chooses a drive or folder and starts a scan. Progress shows discovered items and elapsed time without inventing a completion percentage. After completion, they select Videos and a minimum size. Selecting a large block reveals its exact path, file size, allocated size, dates, scan age, and protection state. Show in Explorer lets them confirm the item in its original context.

Investigate storage growth

The user opens History, selects two scans of the same root and compatible scan settings, and chooses Compare. The comparison lists additions, removals, size changes, and confirmed renames. A growth map uses area for positive growth and explicitly labels this different metric. Shrinking items appear in a separate list. Incomplete scans explain where changes cannot be established.

Review a cleanup selection

The user selects eligible files, then chooses Review selection. The dialog lists exact paths, count, sizes, and any blocked items. Duplicate selections are collapsed to avoid repeated actions. Version 1 supports file recycling only. Folder recycling is later work and requires complete, unfiltered enumeration and review of its contents.

The confirmation button says Move 3 files to Recycle Bin. A result view distinguishes succeeded, skipped, and failed items. The application rechecks available space and refreshes affected folders. It must explain: “Items in Recycle Bin still occupy space until the bin is emptied.” Recovery uses Open Recycle Bin; there is no promise of a universal in-app undo.

Understand an app footprint

In Apps, the user selects a recognized app. Details list the installation paths actually measured and mark coverage as Partial. Shared or uncertain paths remain unattributed rather than being assigned based on similar names. The action is Open installed apps settings. App directories cannot be recycled through this interface.

7 Item details and interaction

The panel includes name, type, exact path, logical bytes, allocated bytes when known, modification date, access date with reliability, attribution, hard-link/shared-storage notice, and completeness. Show scan timestamp near metadata. A folder additionally shows whether displayed size is filtered or total.

Provide Show in Explorer, Copy path, Pin against cleanup, Add to review, and Open installed apps settings when relevant. Opening executable files or scripts is not a default action. File properties are a Windows Shell action. Never label an item as safe to delete solely because it is old or large.

Search uses Ctrl plus F. F5 rescans after confirmation if a scan is already running. Escape dismisses a drawer or dialog; cancellation of a scan uses its explicit control. Space toggles an eligible selection in the list. Delete opens review and never immediately removes files. Dialog focus is trapped and restored to its initiating control.

The list is the primary accessible equivalent to the map. Support keyboard navigation, visible focus, screen-reader names, high contrast, reduced motion, and sorting by size, name, date, and category. Map tooltips must also be available through selection. Do not require hover or color perception to complete a task.

8 Visual system

Use Segoe UI with a 14 px body size, 12 px secondary labels, and 20 to 28 px section titles. Use neutral surfaces, dark text, a restrained green primary action, and the green age scale. Target readable contrast for text on every shade; choose white or dark text per block. Apply an 8 px spacing scale, 6 px control radii, and 32 to 36 px minimum control height. Standard text contrast should meet WCAG AA; test focus and component boundaries as well.

Support system light and dark appearance. The initial wireframe illustrates light mode. High contrast replaces decorative shades with system colors and explicit bucket labels. Disable layout animation under reduced motion. Keep any other transitions short and avoid animating blocks while the user is selecting them.

9 Validation and release review

Run usability sessions with at least five Windows users using a controlled sample folder. Have each find the largest file, explain what its green shade means, identify a growth source, and review a removal selection. Target at least four of five completing each task without instruction. No participant should infer that pale green automatically means safe to delete; any such interpretation requires revising the legend or copy.

Review 1024 × 700 and 1280 × 800 layouts, Windows scaling from 100 to 200 percent, keyboard-only operation, Narrator, dark mode, and high contrast. Check labels for very long names, unavailable dates, inaccessible folders, zero matches, and disconnected drives.

The design is ready for implementation when scope is consistent with the specification, every primary action has a defined result and failure state, and the map can be understood through its list equivalent.

10 Decisions to revisit

The first implementation should validate treemap readability, allocated-size performance, app attribution coverage, and the proposed technology stack. Frequency tracking, automated recommendations, commercialization, and the macOS schedule remain future decisions. None is required to begin the Windows scan and visualization prototype.
